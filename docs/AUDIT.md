## P0 — критическое (ломает продукт целиком)

### P0-1. Неверный `SUPABASE_URL` → все операции с БД падают молча
`server.js:24`, `.env`

В `.env` лежит `SUPABASE_URL=https://<ref>.supabase.co/rest/v1/` (с суффиксом). `createClient` дописывает `/rest/v1` сам, получается двойной путь, и каждый запрос возвращает
`{"code":"PGRST125","message":"Invalid path specified in request URL"}`.

Последствия (проверено):
- `supabase.from('users')...` всегда `data = null` → **логин невозможен** («Неверные данные»), регистрация отдаёт «Ошибка БД»;
- лидерборд и ордера всегда пустые (`data || []`), хотя в БД **5 пользователей и 1 ордер**;
- ошибки нигде не логируются, поэтому баг невидим.

Доказательство: прямой REST к корню домена те же таблицы отдаёт — `users` 5 строк, `orders` 1 строка.

**Фикс:** в `.env` оставить только `https://<ref>.supabase.co`; на старте делать один health-запрос и падать, если БД недоступна; логировать `error` из каждого вызова.

### P0-2. Пароли хранятся и отдаются в открытом виде
`server.js:201-208`, `server.js:222-225`, `public/app.js:7`

- в `users.password` — **плейнтекст** (проверено: 7 символов, не bcrypt);
- `/api/auth/register` и `/api/auth/login` возвращают **всю строку** `users`, включая `password` → фронт кладёт её в `localStorage.currentUser` (`app.js:427`);
- `/api/leaderboard` делает `.select('*')` и отдаёт эти строки публично → **утечка паролей всех пользователей любому посетителю**, как только БД заработает.

Это не «фича на потом», а активная утечка. Минимум: убрать `password` из всех ответов и `.select('*')`. Полноценно — хеширование + сессии (см. план).

### P0-3. Нет аутентификации: любой правит чужой аккаунт по email
`server.js:211-239`

Личность определяется `email` из тела запроса. Итого:
- `POST /api/update-portfolio` с чужим email — перезапись портфеля, `return_percent`, бейджей;
- `GET /api/orders/:email` — чтение чужих заявок;
- `POST /api/orders` — создание заявки от чужого имени;
- `DELETE /api/orders/:id` — отмена чужой заявки.

Токена/сессии/подписи нет вообще. Плюс `cors()` без ограничений и отсутствие rate limit на `/api/auth/*` → перебор паролей.

### P0-4. Портфель живёт на клиенте → лидерборд читерится
`public/app.js:8,351-374,465-472`, `server.js:211-221`

Клиент хранит `cash/holdings` в `localStorage` и целиком присылает их на сервер. Достаточно поправить `localStorage` (cash = 1e9) и вызвать `syncPortfolio()` — топ инвесторов сломан. `return_percent` тоже считается на клиенте (`calcReturnPercent`).

Побочно: `cash` всегда в USD, но списание идёт по цене в RUB/EUR → покупка SBER за 250 «долларов» при цене 250 ₽.

### P0-5. Заявки без валидации → отрицательные `shares`/`target_price`
`server.js:230-235,240-269`, `public/app.js:383-396`

`POST /api/orders` принимает что угодно: `shares: -10` даёт `cost < 0` → на «покупке» кэш **растёт**. Строковые цены, `NaN`, нули — всё проходит. Дополнительно в исполнителе:
- `p.portfolio` у нового пользователя `null` → `p.cash` бросает исключение → внешний `catch` глотает → **обработка всех заявок навсегда останавливается**;
- `p.history.push` падает, если `history` отсутствует;
- при частичной продаже `totalCost` не уменьшается → средняя цена и P&L врут;
- нет транзакций/блокировок → при двух инстансах одна заявка исполнится дважды.

### P0-6. Сервер падает от ошибки WebSocket (воспроизведено)
`server.js:276-281`

У клиента Finnhub WS нет обработчика `'error'`. В живом запуске Finnhub ответил `429 Too Many Requests`, событие `error` осталось необработанным и **процесс умер**:

```
Error: Unexpected server response: 429
    at ... ws/lib/websocket.js:949
Node.js v24.21.0
```

Там же: `JSON.parse(raw)` без `try` (битое сообщение = краш), нет `ping/pong` (мёртвые соединения копятся), реконнект каждые 3 с без backoff, подписка ровно 50 символов (`slice(0,50)`) — это лимит бесплатного тарифа Finnhub, отсюда и 429.

На фронте (`app.js:13-27`) у `ws` нет `onclose/onerror` и реконнекта: после любого обрыва **цены замирают навсегда** до перезагрузки страницы.

## P1 — функционал не работает (пользователь это видит)

### P1-1. Российский рынок полностью мёртв (TLS)
`server.js:53-60,101-111`

`iss.moex.com` отдаёт цепочку от **Russian Trusted Sub CA (Минцифры)**. Node не использует хранилище сертификатов Windows, поэтому axios падает с `self-signed certificate in certificate chain`, `cached()` это глотает и возвращает `null` → `/api/quote/RU/SBER` = 404, `/api/candles/RU/SBER` = `null`, тепловая карта RU пустая, цены в портфеле по RU = 0.

Проверено: с отключённой проверкой те же запросы работают (SBER — 200, свечи — 108 строк).

**Фикс:** `NODE_EXTRA_CA_CERTS` с корневым сертификатом + собственный `httpsAgent`, и не глотать ошибки.

### P1-2. Крипта и валюта не работают вообще
`server.js:66-73`

- `FCS_API_KEY` невалиден: `{"status":false,"code":101,"msg":"You have not supplied a valid API Access Key."}` → все CRYPTO/FOREX котировки = 404;
- для forex-эндпоинта отправляется `BTCUSDT` (`s.replace('BINANCE:','')`) — такой пары там нет, нужно `BTC/USD`;
- `parseFloat(data.o)` при отсутствии `o` даёт `NaN` → `percent = NaN` → на фронте `null.toFixed()` рвёт рендер;
- `currency: 'USD'` для `USDJPY` — фактически неверно (котировка в JPY).

### P1-3. Фундаментал по Европе пустой
`server.js:79-83`

Eulerpool отвечает **403** (Cloudflare-челлендж, запрос без нормального `User-Agent`) → `catch` возвращает `{symbol}`. В UI все метрики EU — «—». То есть 50 европейских бумаг без фундаментала.

### P1-4. Кнопка «Скачать CSV» падает
`public/index.html:99`

`exportCSV` вызывается, но **не объявлена нигде** в `app.js` → `ReferenceError`. Это не «доработка», функции нет.

### P1-5. Радар — декорация
`public/app.js:216-219`

Вердикт меняется, а гейдж всегда рисует `33/33/33` — статичная картинка, стрелка не двигается.

### P1-6. Объём — заглушка
`server.js:136` (`volume: null`), `app.js:174`

В свечах объём есть (`value/volume` у MOEX, `volume` у Yahoo), но он выбрасывается, и в «Техническом» всегда «—».

### P1-7. Кнопка «График Цены» ничего не делает
`public/app.js:185-206`

`loadMainChart(type)` игнорирует `type`, рисует всегда одно и то же; других режимов (линия/свечи/лого) нет.

### P1-8. Мёртвые тикеры в списках
Проверено запросами:

| Тикер | Факт |
|---|---|
| `LVMH.PA` (EU) | 404 у Yahoo — дубль `MC.PA` (LVMH торгуется как MC.PA) |
| `UG.PA` (EU) | 404 — Peugeot больше не существует, это Stellantis (`STLAP.PA`) |
| `POLY`, `AGRO`, `DZRL`, `VSMZ`, `ELTZ` (RU) | нет ни одной торгуемой доски на MOEX → в карточках вечное «—» |

5 из 50 в RU и 2 из 50 в EU — битые. `createCard` при этом молча показывает прочерки, без пометки «тикер недоступен».

### P1-9. Невалидный тикер = «успех»
`server.js:74-75`

Finnhub на неизвестный символ отдаёт `{c:0,d:null,dp:null}`, код возвращает 200 с `price:0`. Фронт считает это валидной ценой (0) и учитывает её в портфеле.

### P1-10. Кэш и свечи: дубли запросов и игнор `days`
`server.js:93-122`

- для не-RU `days` не используется: всегда `range:'1y'`, при этом ключ кэша включает `days` → график (60) и радар (365) тянут одно и то же **дважды**;
- `/api/candles` не принимает `days` из query;
- `cached()` не кэширует ошибки и не склеивает одновременные запросы: 12 карточек + тепловая карта на один и тот же символ дают пачку параллельных вызовов к внешнему API → 429;
- 1 год дневных свечей держится в кэше 60 секунд — бессмысленно.

### P1-11. Средняя цена после продажи ломается
`server.js:259-262`

При продаже `shares` уменьшаются, а `totalCost` — нет. Средняя цена = `totalCost/shares` раздувается, P&L после любой частичной продажи неверный. Тот же баг в клиентском `executeTrade` (`app.js:362-367`).

### P1-12. `return_percent` считается до загрузки котировок
`app.js:425-436`, `351-374`, `465-472`

`processAuth`/`executeTrade` вызывают `fetchPortfolioQuotes()` **без await** и сразу `syncPortfolio()`. В этот момент `allQuotes` пуст → стоимость активов = 0 → в лидерборд уходит `-100%`. Дальше не пересчитывается, пока пользователь не обновит вкладку.

### P1-13. Дубли `id` в DOM
`app.js:85`, `509-518`

Карточки избранного и карточки вотчлиста используют одинаковые `id="wl-price-AAPL"`, `id="wl-change-..."`, `id="wl-analysis-..."`. `getElementById` возвращает первый элемент → вторая карточка не обновляется.

### P1-14. `cancelOrder` ломается на UUID
`app.js:410`

`onclick="cancelOrder(${o.id})"` — если `orders.id` типа `uuid` (а судя по Supabase, это вероятно), в HTML попадает `cancelOrder(3f2a...)` → `SyntaxError`. Нужны кавычки либо `data-id` + делегирование.

## P2 — безопасность и корректность данных

### P2-1. XSS через RSS
`app.js:493-498`

Заголовок, `image` и `url` из CNBC вставляются в `innerHTML` без экранирования (и `href` без проверки схемы). Плюс весь проект на инлайновых `onclick` — CSP включить нельзя.

### P2-2. jQuery 1.11.1 и лицензия CanvasJS
`index.html:181-182`

- jQuery **1.11.1 (2014)** с известными XSS-CVE (CVE-2015-9251, CVE-2019-11358, CVE-2020-11022/11023) — и он вообще не используется;
- Chart.js подключён с CDN, хотя есть в `node_modules`;
- CanvasJS StockChart — **платный для коммерческого использования**, стоит свериться с лицензией до публикации.

### P2-3. Валюты смешаны
`app.js:242-269`, `309-340`

Все суммы выводятся с `$`, хотя среди бумаг есть ₽ и €: `$250.00` для SBER, `$190.08` для SAP. Итоговая стоимость портфеля складывает разные валюты. Нужна базовая валюта и конвертация (ЦБ РФ / ECB — бесплатно).

### P2-4. Задержка данных не раскрыта
MOEX ISS для TQBR по умолчанию отдаёт данные **с задержкой ~15 минут** (не realtime). Сейчас UI показывает их как текущую цену без пометки. Для финансового продукта это фактическая неточность, нужен `asOf` + бейдж «задержка 15 мин».

### P2-5. Мелкие, но реальные
- `MAX`-`viewport` с `maximum-scale=1.0, user-scalable=no` (`index.html:5`) — блокирует зум, нарушает доступность.
- `logout()` не чистит `localStorage.portfolio` → следующий человек на этом устройстве видит чужой портфель.
- `openProfile()` берёт доходность из DOM скрытой вкладки → показывает устаревшее/нулевое.
- `findMarketForSymbol` по умолчанию `'US'` → для символа вне списков тянет котировку не с того рынка.
- `updatePortfolioUI` перестраивает таблицу и обновляет Chart.js **каждую секунду** от WS → джанк и мигание фокуса.
- `executeTrade`/`updatePortfolioUI` используют `tbody.innerHTML +=` в цикле — O(n²).
- `setInterval(fetchPortfolioQuotes, 30000)` дублирует WS.
- `history` пишется, но нигде не показывается.
- `switchTab` требует логин для портфеля, но `processAuth` не проверяет, что сервер вернул портфель нужной формы.
- `heat-tile` для крипты нормирует интенсивность по 3% — для BTC это шум.

## P3 — инфраструктура и гигиена

- **Мёртвые зависимости:** `mongoose` (9.12.0, нигде не `require`), `@supabase/ssr`, `bcryptjs` (объявлен, не используется), `chart.js` (подключён с CDN вместо пакета). `db.json` — остаток прототипа, не используется.
- **Нет схемы БД/миграций** в репозитории → новый разработчик не поднимет проект. Нет `.env.example`.
- **Секреты в OneDrive:** `.env` синхронизируется в облако; сам проект в OneDrive — `node_modules` даёт тысячи мелких файлов, конфликты синка и медленный старт (наблюдал задержку старта сервера).
- **Нет тестов, линтера, README, CI.** Расчёты (P&L, ордера, индикаторы) не покрыты ничем.
- **Нет `/api/health`, нет логирования, нет graceful shutdown, пустые `catch {}`** в 12 местах — любая поломка невидима (что и подтвердилось).
- **Нет `compression`, rate limit, helmet**; `server.listen(PORT, '0.0.0.0')` открывает сервис в локальную сеть.
- Express 4, CommonJS, монолит на 282 строки, вся вёрстка в одном `app.js` на 561 строку — при добавлении фич из плана это станет неподъёмным.
