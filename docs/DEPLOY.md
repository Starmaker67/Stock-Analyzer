# Деплой на Render (бесплатный тариф)

## Что изменилось и требует внимания

1. **`SUPABASE_URL` теперь нормализуется в коде** — даже если в переменной остался путь `/rest/v1/`, клиент его отрежет. Но лучше исправить значение: `https://<ref>.supabase.co` без пути.
2. **Нужен `AUTH_SECRET`.** Если его нет, сервер сгенерирует производный ключ и напишет предупреждение в лог. Производный ключ работает, но при смене `SUPABASE_KEY` все сессии станут недействительны. Сгенерировать:
   ```
   node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
   ```
3. **Пароли переведены в bcrypt.** Пять существующих аккаунтов сохранены: их пароли не менялись, вход работает как раньше (проверено реальным логином).
4. **Сертификат MOEX** лежит в репозитории: `certs/russian-trusted-ca-bundle.pem`. Без него российский рынок отдаёт 404. Файл публичный (корневой сертификат Минцифры), секретов не содержит.

## Переменные окружения в Render

| Переменная | Обязательна | Значение |
|---|---|---|
| `SUPABASE_URL` | да | `https://<ref>.supabase.co` (без `/rest/v1`) |
| `SUPABASE_KEY` | да | secret-ключ Supabase |
| `FINNHUB_KEY` | да | ключ Finnhub (США + WS) |
| `AUTH_SECRET` | да | случайные 48 байт base64url |
| `NODE_ENV` | да | `production` |
| `PORT` | нет | Render задаёт сам |
| `BCRYPT_ROUNDS` | нет | `11` |
| `SESSION_DAYS` | нет | `30` |
| `ENABLE_FINNHUB_WS` | нет | `true`; поставьте `false`, если в логах `429` от Finnhub |
| `LOG_LEVEL` | нет | `info` |

`EULERPOOL_KEY` и `FCS_API_KEY` больше не нужны: Eulerpool блокирует бесплатные запросы (403), FCS-ключ невалиден, его заменили Binance и ECB.

## Особенности бесплатного тарифа Render

- **Засыпание через ~15 минут без запросов.** Следствия:
  - первый запрос после сна — 30–60 секунд (cold start);
  - WebSocket-клиент переподключится сам (в UI появится баннер «Нет соединения»);
  - кэш в памяти обнуляется, котировки загрузятся заново;
  - **лимитные заявки не исполняются, пока сервис спит.** Для симулятора это приемлемо, но в интерфейсе стоит об этом сказать.
  - если нужно, чтобы не засыпал — пинг раз в 10–14 минут (UptimeRobot, cron-job.org) на `/api/health`.
- **Один инстанс, 512 МБ RAM.** Кэш в памяти рассчитан на это; Redis пока не нужен.
- **HTTPS терминируется на Render**, cookie сессии выставляется с `Secure` автоматически (`trust proxy` включён).
- **Диск эфемерный** — ничего важного на диск не пишем, все данные в Supabase.

## Проверка после деплоя

1. `GET /api/health` → `{"ok":true,"db":{"ok":true}}`. Если `db.ok:false` — неверные `SUPABASE_URL`/`SUPABASE_KEY`.
2. `GET /api/quote/RU/SBER` → цена в рублях, `delayed:true`. Если 404 — не подхватился CA-бандл.
3. `GET /api/quote/CRYPTO/BINANCE:BTCUSDT` → цена с Binance.
4. Вход существующим аккаунтом → должен работать со старым паролем.
5. В ответах `/api/leaderboard` **не должно быть** поля `password`.

## Локальная разработка

```
npm install
cp .env.example .env      # заполнить ключи
npm start
```

Проверки:

```
node scripts/smoke-test.js            # 29 проверок API (нужен запущенный сервер)
node scripts/check-frontend.js        # сверка HTML/JS/CSS
node scripts/test-order-executor.js   # сквозная проверка лимитных заявок (~2.5 мин)
node scripts/migrate-passwords.js     # проверка паролей (без --apply ничего не меняет)
```
